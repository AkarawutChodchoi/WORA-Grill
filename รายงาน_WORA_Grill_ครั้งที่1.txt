4. ข้อมูลทางเทคนิค
--------------------------------------------------------------------
ภาษา/เครื่องมือ : TypeScript ทั้งระบบ
ฝั่งเซิร์ฟเวอร์ : Node.js + Fastify 5, WebSocket (เรียลไทม์)
ฝั่งหน้าจอ     : React 19 + Vite + Tailwind CSS 4 (ใช้ผ่านเบราว์เซอร์ ติดตั้งเป็นแอป PWA ได้)
ฐานข้อมูล      : PostgreSQL ผ่าน Drizzle ORM
                 - ไม่ตั้งค่า = ใช้ PGlite (Postgres ฝังในเครื่อง เก็บที่ data\pglite)
                 - ใช้งานจริงหลายเครื่อง/หลายสาขา = แนะนำ PostgreSQL 15+
การเก็บเงิน     : เก็บเป็นสตางค์ (จำนวนเต็ม) ไม่ใช้ทศนิยมแบบ float
Migration      : 12 ไฟล์ (server\drizzle) เดินหน้าอย่างเดียว
โครงสร้างโฟลเดอร์ :
  server\   API, โครงสร้างฐานข้อมูล, migration, ชุดทดสอบ (server\test)
  web\      หน้าจอ: หลังร้าน, POS, จอครัว, เมนู QR ลูกค้า, หน้าคิว, หน้าจองโต๊ะ
  shared\   ตรรกะที่ใช้ร่วม (คำนวณยอด, โปรโมชัน, PromptPay, สิทธิ์)
  docs\     แผนงาน, โครงสร้างข้อมูล, คำอธิบายโมดูล, คู่มือการติดตั้ง/ดูแลระบบ
  scripts\  สคริปต์ build และทดสอบ end-to-end


5. ข้อมูลที่ต้องใช้ — (ก) สิ่งที่ต้องมีเพื่อเปิดใช้ระบบ
--------------------------------------------------------------------
5.1 เครื่องและซอฟต์แวร์
  - คอมพิวเตอร์ที่เป็นเซิร์ฟเวอร์ในร้าน (หรือ Cloud) ติดตั้ง Node.js เวอร์ชัน 22 ขึ้นไป
  - (แนะนำ) PostgreSQL 15+ ถ้าใช้หลายเครื่อง/หลายสาขา
  - แท็บเล็ต/คอมพิวเตอร์สำหรับ POS, จอครัว, พนักงานเสิร์ฟ (ใช้เบราว์เซอร์ Chrome/Edge)
  - เครือข่าย LAN/Wi-Fi ในร้าน; ถ้าเปิดให้เข้าจากภายนอก ต้องมีโดเมนและ HTTPS

5.2 คำสั่งติดตั้งและเปิดใช้งาน (รันในโฟลเดอร์ "WORA Grill" ใส่เครื่องหมายคำพูดเพราะชื่อมีช่องว่าง)
  ทดลอง/พัฒนา:
    cd "C:\Claude-Home\restaurant\WORA Grill"
    npm install
    copy .env.example .env          (แก้ NODE_ENV=development)
    npm run db:migrate
    npm run db:seed                 (ไม่บังคับ: สร้างร้านตัวอย่าง DEMO พิมพ์รหัสผ่านเจ้าของ
                                     และ PIN พนักงานให้ครั้งเดียว — ให้จดเก็บไว้)
    npm run dev                     แล้วเปิด http://localhost:5173
  ใช้งานจริง:
    npm ci
    npm run build
    npm run db:migrate              (สำรองข้อมูลก่อนทุกครั้ง)
    npm start                       เปิดที่ http://<IP เครื่อง>:3000
  ถ้าไม่ได้สร้างร้านตัวอย่าง หน้าแรกจะให้ตั้งค่า ชื่อร้าน สาขาแรก และบัญชีเจ้าของ

5.3 ค่าตั้งค่า (.env) — ดูตัวอย่างเต็มใน .env.example (ห้ามใส่รหัสลับจริงลงใน git)
  PORT=3000                       พอร์ตของระบบ
  DATABASE_URL=                   ว่าง = PGlite ในเครื่อง / ใส่ค่าเมื่อใช้ PostgreSQL
  PGLITE_DIR=./data/pglite        ที่เก็บฐานข้อมูลในเครื่อง
  UPLOAD_DIR=./data/uploads       ที่เก็บรูปเมนู
  SESSION_TTL_HOURS=12            อายุการเข้าสู่ระบบ
  COOKIE_SECURE=false             ตั้ง true เมื่อใช้ผ่าน HTTPS
  TRUST_PROXY=false               ตั้งเป็นจำนวน proxy (เช่น 1) เมื่ออยู่หลัง reverse proxy
  PUBLIC_BASE_URL=                ที่อยู่เว็บที่จะพิมพ์ลง QR โต๊ะ/บัตรคิว
  OPN_SECRET_KEY=, OPN_WEBHOOK_SECRET=        PromptPay ยืนยันอัตโนมัติ (ว่าง = ปิด)
  DELIVERY_WEBHOOK_SECRET=                    รับออเดอร์ Grab/LINE MAN/Shopee (ว่าง = ปิด)
  LINE_CHANNEL_ACCESS_TOKEN=, LINE_NOTIFY_TO= แจ้งเตือนพนักงานทาง LINE (ว่าง = ปิด)
  AUTO_KITCHEN_PRINT=true                     พิมพ์ใบครัวอัตโนมัติเมื่อมีเครื่องพิมพ์ครัว

5.4 บัญชี/สัญญาบริการภายนอก (ต้องให้เจ้าของร้านจัดหา — ระบบปิดไว้จนกว่าจะตั้งค่า)
  - Opn Payments (Omise) : บัญชีร้านค้า + Secret Key + Webhook Secret
                            (ถ้าไม่มี ใช้ PromptPay แบบแคชเชียร์กดยืนยันยอดเองได้ทันที)
  - GrabFood / LINE MAN / ShopeeFood : สัญญาพาร์ทเนอร์ API + ระบบตัวกลาง
  - LINE Official Account : Channel Access Token + ID ผู้รับแจ้งเตือน
  - เครื่องพิมพ์ความร้อนแบบ LAN (ESC/POS) : IP + ค่า code page ภาษาไทยของรุ่นนั้น
  - ลิ้นชักเงินที่ต่อกับเครื่องพิมพ์ใบเสร็จ
  - เครื่อง EDC : ยังไม่เชื่อมอัตโนมัติ (บันทึกเป็นบัตร + Approval code)


6. ข้อมูลที่ต้องใช้ — (ข) ข้อมูลร้านที่ต้องเตรียมกรอกเข้าระบบ
--------------------------------------------------------------------
6.1 ข้อมูลร้าน/สาขา (เมนู ระบบ → ตั้งค่าร้าน)
  - ชื่อร้านที่แสดงบนใบเสร็จ, ที่อยู่, เบอร์โทร, รหัสสาขา
  - เลขประจำตัวผู้เสียภาษี 13 หลัก (ถ้าจด VAT — ใบเสร็จจะเป็นใบกำกับภาษีอย่างย่อ)
  - รูปแบบ VAT: แยกนอกราคา / รวมในราคา / ไม่คิด และอัตรา (ค่าเริ่มต้น 7%)
  - ค่าบริการ % (ค่าเริ่มต้น 10%) และช่องทางที่คิด (ค่าเริ่มต้นเฉพาะทานที่ร้าน)
  - เพดานส่วนลดที่แคชเชียร์ให้ได้เอง (ค่าเริ่มต้น 20%)
  - PromptPay ID (เบอร์มือถือหรือเลขผู้เสียภาษี) และช่องทางชำระที่เปิดรับ
  - ข้อความหัว/ท้ายใบเสร็จ, เวลาเปิด-ปิดร้าน
  - เวลาเตือนจอครัว (เหลือง/แดง), เปิด/ปิดการสั่งผ่าน QR, ต้องอนุมัติออเดอร์ QR หรือไม่

6.2 เมนู
  - หมวดหมู่, ชื่อเมนู (ไทย/อังกฤษ/จีน), ราคา, รูป, รหัส SKU/บาร์โค้ด
  - สารก่อภูมิแพ้และแท็ก (เผ็ด/มังสวิรัติ/ฮาลาล), สเตชันครัวที่ทำ (ครัวร้อน/เย็น/บาร์/ของหวาน)
  - กลุ่มตัวเลือก (ระดับเผ็ด, ไซซ์, ท็อปปิ้ง + ราคาเพิ่ม), เมนูชุด, ราคา Delivery
  - ช่วงเวลาขาย (เมนูเช้า/Happy hour) ถ้ามี

6.3 โต๊ะ
  - โซน/ชั้น, ชื่อโต๊ะ, จำนวนที่นั่ง, พนักงานประจำโซน

6.4 พนักงาน
  - ชื่อ, บทบาท (เจ้าของ/ผู้จัดการ/แคชเชียร์/เสิร์ฟ/ครัว/สโตร์), สาขา
  - อีเมล + รหัสผ่าน (สำหรับคนใช้หลังร้าน), PIN 4–6 หลัก (สำหรับหน้าร้าน)
  - ตำแหน่ง, รูปแบบและอัตราค่าจ้าง (ใช้คำนวณต้นทุนแรงงานในรายงานเท่านั้น)

6.5 วัตถุดิบและสูตร (ถ้าต้องการตัดสต็อกและดู Food cost)
  - รายการวัตถุดิบ, หน่วยเก็บ (g/ml/ชิ้น), การแปลงหน่วย (1 กก. = 1000 ก., 1 ลัง = 24 ขวด)
  - จุดสั่งซื้อ, ยอดคงเหลือเริ่มต้นและราคาทุน
  - สูตรต่อจาน (วัตถุดิบ + ปริมาณ), สูตรของตัวเลือกเสริม (เช่น เพิ่มไข่ = ไข่ 1 ฟอง)

6.6 จัดซื้อ
  - รายชื่อซัพพลายเออร์, ผู้ติดต่อ, เครดิต (วัน), สินค้า/หน่วย/ราคาที่ซื้อ

6.7 สมาชิกและโปรโมชัน (ถ้าใช้)
  - อัตราแต้ม, มูลค่าแต้ม, ระดับสมาชิก, อายุแต้ม, โปรโมชัน/คูปองที่จะใช้

6.8 อุปกรณ์
  - ลงทะเบียนแท็บเล็ตแต่ละเครื่องเป็น POS/พนักงานเสิร์ฟ/จอครัว (ระบบ → อุปกรณ์)
  - IP ของเครื่องพิมพ์ใบเสร็จ/ครัว แล้วกด "ทดสอบพิมพ์"


7. ข้อจำกัดและสิ่งที่ยังไม่ทำ
--------------------------------------------------------------------
- ยังไม่ได้ทดลองหน้าจอบนเบราว์เซอร์/แท็บเล็ต/จอครัวจริง และยังไม่ได้ทดสอบโหลด/เจาะระบบ
- ไม่ทำโดยเจตนา (ต้องมีกฎและการตรวจด้านกฎหมายก่อน): เงินเดือน, OT, ประกันสังคม,
  ภาษีหัก ณ ที่จ่าย, การแบ่งทิป, บัตรกำนัล/เงินเติมล่วงหน้า
- ยังไม่เชื่อม: e-Tax Invoice, โปรแกรมบัญชี (FlowAccount/PEAK/Express), อีเมล,
  การส่งโปรโมชันทาง LINE/SMS, ซิงก์เมนูกับแพลตฟอร์ม Delivery, เครื่อง EDC,
  จอลูกค้า, เครื่องพิมพ์ Bluetooth
- รายงานภาษีเป็นข้อมูลประกอบ ไม่ใช่แบบ ภ.พ.30 และไม่รับรองความถูกต้องทางกฎหมาย
- โหมดออฟไลน์: รับออเดอร์/ส่งครัว/รับเงินสดได้ แต่ Void ส่วนลด คืนเงิน
  และการชำระที่ไม่ใช่เงินสดต้องออนไลน์ เงินสดที่รับตอนออฟไลน์จะ "ยังไม่ยืนยัน" จนกว่าจะซิงก์
- รันเซิร์ฟเวอร์ได้ครั้งละ 1 ตัว (ถ้าต้องขยายหลายเครื่องต้องเพิ่ม Redis)
- การลบข้อมูลลูกค้าตามระยะเวลา (PDPA) ยังไม่ตั้งเวลาอัตโนมัติ ต้องกดลบตามคำขอ


8. ขั้นตอนถัดไปที่แนะนำ
--------------------------------------------------------------------
1) ทดลองใช้ร้านตัวอย่าง (npm run db:seed) บนแท็บเล็ตและจอครัวจริง เก็บข้อเสนอแนะ
2) เตรียมข้อมูลร้านตามข้อ 6 แล้วกรอกในระบบจริง (เริ่มจากตั้งค่าร้าน → เมนู → โต๊ะ → พนักงาน)
3) จัดหาเครื่องพิมพ์ LAN และทดสอบภาษาไทย/ลิ้นชักเงิน
4) ตัดสินใจเรื่องบัญชี Opn / LINE / Delivery แล้วจึงใส่ค่าใน .env
5) ตั้งสำรองข้อมูลประจำวัน (npm run db:backup) และทดลองกู้คืน
6) ถ้าจะเปิดให้เข้าจากภายนอก: ตั้ง HTTPS แล้วตั้ง COOKIE_SECURE=true, TRUST_PROXY=1
7) เมื่อพร้อมแล้วค่อยพิจารณา push ขึ้น GitHub / deploy (ยังไม่ได้ทำตามที่ตกลงไว้)
